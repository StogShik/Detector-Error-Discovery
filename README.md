# Detector Error Discovery — компактное решение

Ранжирование ошибочных детекций людей, голых кистей, чашек и подносов на кадрах кафе. Чем выше `score`, тем раньше бокс должен попасть на проверку. Выход: CSV с колонками `id,score`, значения от 0 до 1.

В репозитории одна выбранная схема: **3 CatBoost и 6 визуальных моделей**. ROI-регрессор и дополнительный active-person детектор исключены. Веса локально обученных моделей уже включены; публичный Grounding DINO загружается автоматически по закреплённой ревизии.

## Установка

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/StogShik/Detector-Error-Discovery.git
cd Detector-Error-Discovery
uv sync --extra vision --extra dev
uv run ded verify
```

`uv.lock` фиксирует зависимости. Варианты устройства: `--device auto`, `cpu`, `mps`, `cuda:0`. MediaPipe работает на CPU.

## Воспроизведение готовой отправки

```bash
uv run ded replay --output outputs/replayed.csv
uv run pytest -q
```

Режим `replay` пересчитывает три CatBoost и итоговую композицию по сохранённым промежуточным предсказаниям визуальных моделей. Он проверяет совпадение всех 362 скоров с `reference/submission.csv` с допуском `1e-12`. Для этого режима достаточно `uv sync --extra dev`, без установки визуальных зависимостей.

## Полный запуск по изображениям

Распакуйте исходный набор соревнования отдельно. В `DATA_DIR` должны находиться:

```text
test.csv
test_frames.csv
test_context.csv
test_stream_predictions.csv
sample_submission.csv
<frame_id>.jpg
```

```bash
uv run ded download
uv run ded predict --data-dir /path/to/DATA_DIR --output outputs/submission.csv
```

Запуск самостоятельно строит геометрические и временные признаки, выполняет все шесть визуальных моделей и создаёт отправку. Он не читает `reference/features.csv`, `reference/signals.csv` или старые экспериментальные каталоги. Кэш `.cache/predictions/` привязан к содержимому входных признаков, изображений и конфигурации моделей; прерванный запуск можно продолжить.

Полный запуск по исходным изображениям проверен на Apple M4/MPS: все **362** скора совпали с контрольным компактным CSV, максимальная абсолютная разница **0.0**. Это проверка воспроизводимости, а не измерение Public AP.

Для предсказаний не нужны `train.csv`, ручные боксы или метки теста. Класс `table` используется как контекст из stream-файла и исключён из выходных строк. Координаты входных боксов — канонические 1280×720.

## Схема

1. Три CatBoost по confidence, геометрии, пересечениям, связям с людьми/руками/предметами/столами. Базовый скор: `0.45 * rank(1-confidence) + 0.55 * rank(mean(CatBoost))`.
2. Классификатор одежды проверяет детекции `person`; вероятность одежды повышает подозрительность бокса.
3. Три YOLO-проверяющих: все четыре класса, отдельные люди, мелкие объекты на тайлах. Вес проверки в смеси — 0.4.
4. Общий замороженный Grounding DINO проверяет людей на полном кадре и мелкие объекты на увеличенных фрагментах. Веса: люди 0.5, руки 0.25, чашки 0.5; для подносов применяется перестановка скоров внутри дня.
5. MediaPipe на четырёх поворотах находит ключевые точки кистей. Когда найдена согласованная близкая кисть, её геометрический риск получает вес 0.3. Отсутствие найденной кисти не означает ошибку автоматически.

Сопоставление Grounding DINO с исходными боксами учитывает максимальное число пар при IoU ≥ 0.60 и затем сумму IoU. Для обученных YOLO сохранена проверенная исходная формула сопоставления; замена её на другую меняет результат.

## Экспериментальный вариант геометрии рук

Стандартный режим выше сохранён. Дополнительно доступен `--recipe hand-consensus`: геометрический риск кисти становится более контрастным, а её вес увеличивается с 0.3 до 0.5 по мере подтверждения кисти на нескольких поворотах. Новые веса, модели или дополнительные проходы нейросетей не требуются.

```bash
uv run ded replay --recipe hand-consensus --output outputs/submission_hand_consensus.csv
# Либо полный запуск из изображений:
uv run ded predict --data-dir /path/to/DATA_DIR --recipe hand-consensus --output outputs/submission_hand_consensus.csv
```

Средний локальный AP этого кандидата — **0.959272** против **0.958165** стандартного варианта; улучшились оба дня. Однако условный кадровый bootstrap даёт интервал разницы примерно **[-0.00445; +0.00620]**. Прирост мал и не прошёл заранее заданный порог 0.002 для замены стандартной схемы. Поэтому режим остаётся экспериментальным и включается явно; Public AP пока неизвестен.

Контрольный файл: `reference/submission_hand_consensus.csv`. Воспроизвести локальное сравнение:

```bash
uv run python training/check_hand_recipe.py
```

`reference/hand_recipe_oof.csv` содержит сохранённые предсказания на отложенных TRAIN-днях, не предсказания all-data моделей на собственном train. Другие проверенные изменения — веса смешивания, зеркальный проход и отдельный person-only запрос — не дали устойчивого выигрыша; результаты сохранены в `reference/improvement_trials.json`.

`config.json` содержит порядок признаков, состав моделей и SHA-256 каждого включённого файла. Полный запуск по изображениям и быстрый `replay` используют одну функцию композиции.

## Качество и ограничения

| Вариант | Средний локальный AP по двум дням | Public AP |
|---|---:|---:|
| Полная исходная схема, 8 визуальных моделей + 15 CatBoost | 0.957953 | 0.87853 |
| Эта компактная схема, 6 + 3 | 0.958165 | **пока неизвестен** |

Локально компактная схема получила 0.959957 на 25 октября и 0.956373 на 26 октября. Сокращение выбиралось по допустимой средней потере до 0.003 и потере не более 0.005 на отдельном дне и test-like подмножестве, затем по минимальному числу моделей среди проверенных вариантов. На одном дне результат ниже полного решения, на другом выше.

Это повторно использованная валидация на **198 детекциях**, а не независимая оценка Public. Утверждения о Public 0.87853 относятся к полной исходной схеме; компактный CSV ещё должен пройти отправку. Таблицы сравнения находятся в `reference/pruning_*.csv`. Уменьшение числа моделей не означает пропорционального ускорения: дорогие проходы Grounding DINO сохраняются.
