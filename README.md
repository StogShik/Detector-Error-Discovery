# Detector Error Discovery — компактное решение

Ранжирование ошибочных детекций людей, голых кистей, чашек и подносов на кадрах кафе. Чем выше `score`, тем раньше бокс должен попасть на проверку. Выход: CSV с колонками `id,score`, значения от 0 до 1.

По умолчанию используется компактная схема: **3 CatBoost и 6 визуальных моделей**. ROI-регрессор и дополнительный active-person детектор исключены. Веса локально обученных моделей уже включены; публичный Grounding DINO загружается автоматически по закреплённой ревизии. Отдельные экспериментальные варианты включаются явно.

## Установка

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/StogShik/Detector-Error-Discovery.git
cd Detector-Error-Discovery
uv sync --extra vision --extra dev
uv run ded verify
```

`uv.lock` фиксирует зависимости. Варианты устройства: `--device auto`, `cpu`, `mps`, `cuda:0`. MediaPipe работает на CPU.

## Воспроизведение готовой отправки

```bash
uv run ded replay --output outputs/replayed.csv
uv run pytest -q
```

Режим `replay` пересчитывает три CatBoost и итоговую композицию по сохранённым промежуточным предсказаниям визуальных моделей. Он проверяет совпадение всех 362 скоров с `reference/submission.csv` с допуском `1e-12`. Для этого режима достаточно `uv sync --extra dev`, без установки визуальных зависимостей.

## Полный запуск по изображениям

Распакуйте исходный набор соревнования отдельно. В `DATA_DIR` должны находиться:

```text
test.csv
test_frames.csv
test_context.csv
test_stream_predictions.csv
sample_submission.csv
<frame_id>.jpg
```

```bash
uv run ded download
uv run ded predict --data-dir /path/to/DATA_DIR --output outputs/submission.csv
```

Запуск самостоятельно строит геометрические и временные признаки, выполняет все шесть визуальных моделей и создаёт отправку. Он не читает `reference/features.csv`, `reference/signals.csv` или старые экспериментальные каталоги. Кэш `.cache/predictions/` привязан к содержимому входных признаков, изображений и конфигурации моделей; прерванный запуск можно продолжить.

Полный запуск по исходным изображениям проверен на Apple M4/MPS: все **362** скора совпали с контрольным компактным CSV, максимальная абсолютная разница **0.0**. Это проверка воспроизводимости, а не измерение Public AP.

Для предсказаний не нужны `train.csv`, ручные боксы или метки теста. Класс `table` используется как контекст из stream-файла и исключён из выходных строк. Координаты входных боксов — канонические 1280×720.

## Схема

1. Три CatBoost по confidence, геометрии, пересечениям, связям с людьми/руками/предметами/столами. Базовый скор: `0.45 * rank(1-confidence) + 0.55 * rank(mean(CatBoost))`.
2. Классификатор одежды проверяет детекции `person`; вероятность одежды повышает подозрительность бокса.
3. Три YOLO-проверяющих: все четыре класса, отдельные люди, мелкие объекты на тайлах. Вес проверки в смеси — 0.4.
4. Общий замороженный Grounding DINO проверяет людей на полном кадре и мелкие объекты на увеличенных фрагментах. Веса: люди 0.5, руки 0.25, чашки 0.5; для подносов применяется перестановка скоров внутри дня.
5. MediaPipe на четырёх поворотах находит ключевые точки кистей. Когда найдена согласованная близкая кисть, её геометрический риск получает вес 0.3. Отсутствие найденной кисти не означает ошибку автоматически.

Сопоставление Grounding DINO с исходными боксами учитывает максимальное число пар при IoU ≥ 0.60 и затем сумму IoU. Для обученных YOLO сохранена проверенная исходная формула сопоставления; замена её на другую меняет результат.

## Экспериментальный вариант геометрии рук

Стандартный режим выше сохранён. Дополнительно доступен `--recipe hand-consensus`: геометрический риск кисти становится более контрастным, а её вес увеличивается с 0.3 до 0.5 по мере подтверждения кисти на нескольких поворотах. Новые веса, модели или дополнительные проходы нейросетей не требуются.

```bash
uv run ded replay --recipe hand-consensus --output outputs/submission_hand_consensus.csv
# Либо полный запуск из изображений:
uv run ded predict --data-dir /path/to/DATA_DIR --recipe hand-consensus --output outputs/submission_hand_consensus.csv
```

Средний локальный AP этого кандидата — **0.959272** против **0.958165** стандартного варианта; улучшились оба дня. Однако условный кадровый bootstrap даёт интервал разницы примерно **[-0.00445; +0.00620]**. Прирост мал и не прошёл заранее заданный порог 0.002 для замены стандартной схемы. Поэтому режим остаётся экспериментальным и включается явно; Public AP пока неизвестен.

Контрольный файл: `reference/submission_hand_consensus.csv`. Воспроизвести локальное сравнение:

```bash
uv run python training/check_hand_recipe.py
```

`reference/hand_recipe_oof.csv` содержит сохранённые предсказания на отложенных TRAIN-днях, не предсказания all-data моделей на собственном train. Другие проверенные изменения — веса смешивания, зеркальный проход и отдельный person-only запрос — не дали устойчивого выигрыша; результаты сохранены в `reference/improvement_trials.json`.

`config.json` содержит порядок признаков, состав моделей и SHA-256 каждого включённого файла. Полный запуск по изображениям и быстрый `replay` используют одну функцию композиции.

## Экспериментальная поправка людей: обрезанный низ тела

`person-truncation` добавляет замороженный ByteTrack YOLOX-X, обученный в том числе на CrowdHuman с полными боксами тела. Он обнаруживает случаи, когда исходный детектор оставил голову и торс, а ноги за столом не включил. Поправка повышает риск, если новый детектор уверен, верх и горизонтальное положение боксов совпадают, а низ нового бокса существенно ниже исходного. Формула: `score += 0.5 * evidence * (1-score)`. Остальные классы сохраняют свои скоры.

Можно применить только этот дополнительный детектор к уже готовому CSV, без повторного запуска всего ансамбля:

```bash
uv run ded correct-people --data-dir /path/to/DATA_DIR \
  --base-submission reference/submission_public_087853.csv \
  --output outputs/submission_person_truncation.csv
```

Контрольный результат этой команды — **`reference/submission_person_truncation_publicbase.csv`**. Его база — неизменённая отправка с подтверждённым Public **0.87853**. По присланному пользователем скриншоту поправка тоже получила **0.87853**, без измеренного прироста. Поэтому она остаётся экспериментом и не заменяет стандартную схему. Веса дополнительного детектора (~793 MB) скачиваются автоматически в `.cache/models/` и проверяются по SHA-256; в Git они не включены.

Команда `correct-people` проверена отдельным повторным запуском из этого репозитория на всех 83 тестовых кадрах с людьми: 362 выходные строки, максимальная разница с контрольным CSV **0.0**. У 9 боксов свидетельство обрезанного низа превышает 0.5; остальные поправки слабее. Другие классы совпадают с базовой отправкой точно.

Для компактной схемы доступны оба режима:

```bash
uv run ded replay --recipe person-truncation --output outputs/compact_person.csv
uv run ded predict --recipe person-truncation --data-dir /path/to/DATA_DIR --output outputs/compact_person.csv
uv run python training/check_person_recipe.py
```

|---|---:|---:|
| Компактная: AP людей | 0.94083 → 0.96537 | 0.86077 → 0.90494 |
| Полная с Public 0.87853: AP людей | 0.94430 → 0.96316 | 0.85558 → 0.90570 |

Это сравнение по отложенным TRAIN-дням, всего 84 детекции людей. Из трёх заранее заданных весов 0.35/0.5/0.65 выбран 0.5 на тех же двух многократно использованных днях. Условный кадровый bootstrap разницы общего AP компактной схемы: **[-0.00178; +0.02256]**. Локальный прирост не подтвердился на Public для полной базы; стандартная схема по умолчанию сохранена. Вариант простого смешивания IoU-риска нового детектора оказался слабее: направленный сигнал обрезанного низа дал больший прирост AP людей.

## Новый кандидат: уточнение границ людей через YOLO26x

Готовый файл — **[reference/submission_yolo26x_fusion.csv](reference/submission_yolo26x_fusion.csv)**. База — полная исходная отправка с подтверждённым Public **0.87853**. **Public нового файла пока неизвестен.** Компактная модель по умолчанию сохранена.

Замороженная публичная [YOLO26x](https://docs.ultralytics.com/models/yolo26/) уточняет верхнюю, левую и правую границы уверенно сопоставленных боксов старого person-проверяющего. Эти три координаты усредняются с весом 0.5. Нижняя граница сохраняется: исходная модель учитывает скрытые за столом ноги. Число боксов, confidence и слабые детекции старой модели сохраняются, чтобы не менять её исходное сопоставление. Новый детектор использует confidence ≥ 0.3, пары принимаются при IoU ≥ 0.3. После пересчёта person-ветки применяется общий офсет людям: `(score + 0.05 * is_person) / 1.05`. Он меняет взаимный порядок классов, сохраняя порядок людей между собой и диапазон [0, 1].

| Вариант | Общий AP 25 октября | Общий AP 26 октября | Средний AP |
|---|---:|---:|---:|
| Полная исходная схема | 0.963403 | 0.952504 | 0.957953 |
| Только офсет +0.05 людям | 0.964721 | 0.954975 | 0.959848 |
| Только уточнение YOLO26x | 0.963403 | 0.953583 | 0.958493 |
| YOLO26x и офсет +0.05 | 0.965822 | 0.956126 | **0.960974** |

AP людей второго дня вырос **0.855576 → 0.862130**; первого остался **0.944305**. Дообучение только регрессии боксов YOLO26x на другом TRAIN-дне, усреднение её весов с публичными, YOLO26x-pose и D-FINE-X дали близкие результаты. Выбрана публичная YOLO26x без дообучения: её средний AP отличается от лучшего проверенного адаптированного варианта менее чем на 0.0002. Сравнение: `reference/strong_person_model_comparison.csv`.

Это небольшой исследовательский выигрыш на двух многократно использованных TRAIN-днях. Заранее заданный строгий порог +0.01 среднего AP людей не пройден. Условный кадровый bootstrap разницы общего AP с базой: **[-0.00068; +0.00836]**, с одним офсетом: **[-0.00091; +0.00407]**; интервалы включают ноль. Это не независимое подтверждение качества на Public.

Это не запуск полной схемы на произвольном новом видео. Для общего запуска компактной модели используйте `ded predict`. Обе person-ветки проверены повторным запуском на всех 83 TEST-кадрах; все 362 оценки воспроизведены с допуском `1e-12`. Ручные TEST-метки не используются. Публичные веса YOLO26x (~113 MiB) автоматически загружаются с проверкой SHA-256, в Git не включены.

## Проверка масок SAM 2 — без включения в решение

На 84 TRAIN-детекциях людей (34 кадра) проверен замороженный SAM 2.1 Hiera Tiny: маска по исходному боксу, по независимому боксу Grounding DINO и по двум точкам торса с отрицательными точками соседей. Промпты не использовали GT. Измерялись выход маски за бокс, геометрия её границ, заполненность бокса, согласованность масок и захват соседнего человека. Маска выбиралась по оценке SAM, без выбора по разметке.

Проверены прямые поправки и небольшой LogisticRegression с обучением на другом UTC-дне. Контрольный классификатор использовал те же замороженные признаки детектора, но без масок; предсказания обученных ранжировщиков в его обучение не подавались.

| Вариант | AP людей, 26 октября | Средний общий AP двух дней |
|---|---:|---:|
| База с Public 0.87853 | 0.85558 | 0.95795 |
| Классификатор с признаками маски, вес 0.25 | 0.86356 | 0.95795 |
| Контроль без масок, вес 0.25 | 0.86931 | 0.95805 |

Ни один вариант не прошёл критерий устойчивого улучшения на обоих днях. SAM выделял видимые торсы, тогда как часть GT-боксов включала скрытые за столом ноги. Маски не дали подтверждённой дополнительной пользы относительно контрольных признаков. Новый тестовый CSV не создавался; состав основной модели сохранён.

Повторить сравнение по сохранённым замороженным признакам:

```bash
uv run python training/check_sam_recipe.py
```

Для повторного получения масок нужны исходные TRAIN-изображения и официальный SAM 2. В отдельном окружении либо дополнительно к визуальным зависимостям:

```bash

PYTORCH_ENABLE_MPS_FALLBACK=1 uv run --no-sync python training/check_sam_recipe.py \
  --infer --data-dir /path/to/DATA_DIR
```

Публичный checkpoint (~149 MiB) загружается автоматически и проверяется по SHA-256 из `reference/sam2_person_metadata.json`. `--sam-source` позволяет использовать уже загруженный checkout вместо установки. Результаты и признаки находятся в `reference/sam2_person_*.csv`; веса и маски не включены в Git и не требуются для основного решения.

## Качество и ограничения

| Вариант | Средний локальный AP по двум дням | Public AP |
|---|---:|---:|
| Полная исходная схема, 8 визуальных моделей + 15 CatBoost | 0.957953 | 0.87853 |
| Эта компактная схема, 6 + 3 | 0.958165 | **пока неизвестен** |

Локально компактная схема получила 0.959957 на 25 октября и 0.956373 на 26 октября. Сокращение выбиралось по допустимой средней потере до 0.003 и потере не более 0.005 на отдельном дне и test-like подмножестве, затем по минимальному числу моделей среди проверенных вариантов. На одном дне результат ниже полного решения, на другом выше.

Это повторно использованная валидация на **198 детекциях**, а не независимая оценка Public. Утверждения о Public 0.87853 относятся к полной исходной схеме; компактный CSV ещё должен пройти отправку. Таблицы сравнения находятся в `reference/pruning_*.csv`. Уменьшение числа моделей не означает пропорционального ускорения: дорогие проходы Grounding DINO сохраняются.

## Обучение и источники весов

Инструкции и дополнительные TRAIN-аннотации — в [training/README.md](training/README.md). Исходные изображения и полные таблицы соревнования не включены. Дополнительные скрытые границы людей приблизительные и отмечены в аннотациях.

Новый [набор сложных поз TRAIN](training/annotations/diverse_person/README.md) содержит 129 проверенных наблюдений на 62 ранее не размеченных кадрах. После исключения повторов доступны 42 подтверждённых полных бокса; скрытые границы ещё 72 наблюдений оставлены неизвестными. Отдельный загрузчик готовит 20 кадров с 24 дополнительными целями, сохраняя масштаб и закрывая неопределённых людей. Проведённое дообучение не улучшило основную схему: AP людей второго дня 0.85558 → 0.83982, средний общий AP 0.95795 → 0.95607. Стандартные веса сохранены. Воспроизведение: `uv run python training/train_diverse_person.py --stage evaluate`.

Модели и исходные публичные веса перечислены в [MODELS.md](MODELS.md). Компактная схема не использует генеративные VLM, ручные тестовые метки, ROI-регрессор или active-person модель. Экспериментальная поправка людей использует ещё один публичный замороженный детектор и включается явно.
